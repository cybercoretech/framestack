## Confirmed direction

- FrameStack is a project/repository name, not a trademark or branding exercise.
- The project is a multi-language full-stack framework and development ecosystem.
- Rust-native frontend integrations are in scope, including Leptos and Dioxus.
- TypeScript frontend ecosystems are in scope, including React.
- Multiple backend runtimes and frameworks should be supported through explicit adapters.
- Core architecture must not be coupled to one frontend, backend, database, or hosting provider.
- Cross-language interfaces should use versioned contracts and shared fixtures where practical.
- `AGENT_HANDOFF.md` is local-only and must remain excluded from Git.
- `PROJECT_STATE.md` is the tracked, concise project status.

## Accepted Stage 0 architecture decisions

ADR-0005 through ADR-0008 are accepted.

- **Project model:** directed component graph; component kinds are `application`, `service`, `worker`, and `resource`.
- **Relationships:** `build_dependency`, `runtime_dependency`, and `communicates_with`. The build-dependency graph must be acyclic.
- **Capabilities:** structured provider, requirement, and constraint declarations. The initial vocabulary and operation contract are defined in ADR-0006.
- **Reference stacks:** Leptos + Axum (Rust) and React + Vite + Fastify (TypeScript).
- **Mixed-language verification:** React + Vite frontend communicating with an Axum service, scheduled after the independent reference slices.
- **Manifest and schema:** `framestack.toml`, normalized JSON-compatible representation, JSON Schema Draft 2020-12, plus semantic validation in the core.
- **Tooling:** Rust core/CLI and Cargo workspace; TypeScript packages and pnpm workspace.
- **License:** MIT.
- **Minimum supported Rust:** 1.85 (`rust-version` in `Cargo.toml`), tested in CI alongside stable.
- **Still open:** the minimum supported Node.js version for TypeScript packages, to be set when the first package exists; review/acceptance of ADR-0001 through ADR-0004 remains tracked in the roadmap.

No implementation or integration support is claimed by these architecture decisions alone.

## Documentation platform and standards

- **Decision:** ADR-0009 accepted.
- **Engine:** Docusaurus 3.x.
- **Content:** Markdown + MDX, canonically maintained in `docs/`.
- **Website:** TypeScript + React application under `website/`.
- **Theme:** Custom FrameStack/CyberCore styling.
- **Hosting:** GitHub Pages initially; custom domain later.
- **Search:** Integrated documentation search.
- **Versioning:** Documentation snapshots tied to FrameStack releases.
- **API reference:** Generated where practical, with hand-written conceptual and usage explanations.
- **Release obligations:** Publish documentation snapshots with releases; retain migration guides.
- **Validation target:** CI checks for Markdown/MDX, links, metadata, navigation, site builds, examples, and generated references.

### Documentation standards

The comprehensive documentation standard is maintained at `docs/documentation/STANDARDS.md`. It defines editorial rules, content architecture, tutorial and reference requirements, code-example verification, integration and API documentation, security and accessibility requirements, release versioning, migration guidance, CI validation, and the definition of done.

### Current implementation status

The platform and standards have been formally selected and documented. The Docusaurus application, custom theme, search configuration, hosting workflow, generated reference pipelines, and release snapshot automation are subsequent implementation work; do not represent them as operational until built and verified.
